# 双花瓣配电网 · 仿真工作台

面向 **10 kV 中压配电网典型接线** 的可编辑、可仿真、可演练的单页工作台。
零依赖、零构建，双击 `index.html` 即可运行（推荐 Chrome / Edge）。

## 快速开始

```bash
# 方式一：直接打开
open index.html            # macOS
start index.html           # Windows

# 方式二：起一个本地静态服务（推荐，避免个别浏览器对 file:// 的限制）
python3 -m http.server 8080
# 然后访问 http://localhost:8080/
```

## 公网预览（分享给同事）

仓库根目录的 `index.html` 是零依赖单文件，直接丢到任意静态托管即可。临时分享用内置脚本：

```bash
bash tools/public-preview.sh
```

脚本会在本机 `127.0.0.1:8099` 起一个只暴露 `index.html` 的静态站点，再用
**Cloudflare 快速隧道**（免登录）映射到公网，终端会打印形如
`https://xxx.trycloudflare.com` 的地址，把它发给别人即可打开。

- 隧道地址是**随机生成**的，脚本结束即失效，重跑会换新地址。
- 想用固定域名 / 长期在线，改用 Cloudflare **命名隧道**（需登录账号）或部署到 GitHub Pages / Vercel。
- `.public/` 只是站点根目录（内含指向 `index.html` 的符号链接），已加入 `.gitignore`。

## 图元约定（与典型设计图一致）

- **变电站（10 kV 电源）**：**正方形**，内部竖置 10 kV 母线；**同一段母线**引出 2 回出线，
  电缆末端为**电缆终端头**（端子）并标注**示意性馈线编号**（如 出线1，不使用真实线路号），构成一片花瓣的两端电源。
- **开关站（环网柜）**：**单母线分段、不旋转、可上下镜像**——
  **Ⅰ 段母线（蓝）与 Ⅱ 段母线（青）共线横置**，中间为 **母联（分段开关，横置长条方框：空心=分位、实心=合位）**；
  母线外端为**母线终端**。每段母线 4 个间隔：
  **2 回用户出线（朝外）+ 2 回环网间隔（朝内，一进一出）**。
  断路器**实心 = 合位、空心 = 分位**；出线间隔朝向环网通道，用户间隔朝外。
- **配电房（用户负荷）**：**一个用户出线间隔 = 一个独立负荷**，各画**一个三角形**（顶点背向开关站），
  单电源供电；符号取所属母线段颜色（Ⅰ 段蓝 / Ⅱ 段青），**该回路失电即连同线路一起转灰**。
  每座开关站 4 个用户间隔 → 4 个独立负荷，双花瓣 9 站共 36 个负荷。
- **终端符号**：**电缆终端头** = 电缆末端的端子（白环 + 实心圆，不再画成箭头状）；**母线终端** = 母线末端的一个**小实心方块**（端头封堵）。
- **母联（分段开关）**：横置于两段母线之间，用**横置长条方框**表示，**空心 = 分位（断开）、实心 = 合位（闭合）**
  （双花瓣正常方式为分位/常开），两段母线互为备用。环间联络开关另用橙色虚线表示。

## 双花瓣网架（教科书方式）

- **命名**：全网**示意化命名**——变电站1 / 变电站2、开关站1~开关站9、配电房1 … 配电房36、出线1 / 出线2，
  不使用真实站名与线路号。
- **布置**：两座变电站分列左右，中间是**两排共 9 座开关站**——上排 5 座（开关站1~5，用户朝上）、
  下排 4 座（开关站6~9，用户朝下），环网间隔朝向两排之间的通道。
- **花瓣Ⅰ（变电站1）**：出线1 ⇒ 上排各站 **Ⅰ 段** ⇒ 开关站5 纵向联络 ⇒ 下排各站 **Ⅰ 段** ⇒ 出线2，成环运行。
- **花瓣Ⅱ（变电站2）**：出线1 ⇒ 上排各站 **Ⅱ 段** ⇒ 开关站1 纵向联络 ⇒ 下排各站 **Ⅱ 段** ⇒ 出线2，成环运行。
- **相切**：两片花瓣在每座开关站经**母联开关**相切；正常母联断开，两段互为备用（备自投）。
- **故障**：线路任一段故障由差动保护两端切除，合环运行下**非故障段不停电**；
  一段两路进线全失时，**母联备自投**由另一段接带其负荷。

### 运行方式与保护口径

- 正常方式：**环网合环运行 + 母联断开**；底栏“运行方式”与“校验 / 告警”**由环网开关、母联的真实位置驱动**，
  不再各说各话。双花瓣 / 单花瓣的各环由**同一电源的两回出线**构成，不存在环网开环点，
  故“环网闭环 / 开环”按钮对这两个模板置灰并说明；环网开环点由母联（花瓣间联络）承担，用“母联常开 / 常合”调整。
- 线路段故障：光纤电流差动保护**瞬时切除故障电缆两端开关**，合环运行下非故障段**不停电**。
- 开关站母线故障：母线差动保护跳开该段母线全部开关并**闭锁母联备自投**。
- **母联备自投（按站独立动作）**：故障后逐座检查，凡“一段母线失压、另一段有压”的开关站即合上本站母联，
  由另一段母线接带本站负荷；每合一处都校验**不并列、不向故障区间送电**。母线故障则整站母联被闭锁。
- 画布上的动作标注（①②③）会**自动避让**并画引线连回被标注的开关；右栏「动作过程」为**竖向时间轴**，
  以 `0.00 s` 故障发生为基准，之前为正常运行，之后为保护 / 隔离 / 转供各步。
- **三条入口同一状态机**：① 模拟故障 / ② 隔离故障 / ③ 转供恢复、**单步**、**自动演示**共用一套演练进度，
  任意入口在结束时，开关实态、失电户数、步骤状态、时间轴文案**完全一致**；演练结束后再点“单步”会提示先复位。
- **场景库随拓扑切换**：双花瓣 / 单花瓣 / 双环网 / 单环网 / 单辐射各有对应场景与说明，“故障前”描述随模板生成。
- **拒动 / 越级**（K3 环网开关拒动、R1 出线保护拒动、M3 差动通道故障）按**后备保护越级**处理：
  跳开该段全部进出线并闭锁母联（或越级跳变电站出线），失电范围与文案同源。
- **备自投拒动**（M1）失压段无法转供；**转供容量不足**（M2）先复电、再见机**限电**，
  失电户数与“只能转供 8 个配电房”的说明一致。
- **故障性质**（F1 单相接地不跳闸 → 试拉确认；T1 重合成功；T2 重合不成功 → 加速跳闸后再隔离转供）。
- **运行方式**（O1 预置开环点；O2 母联常合并列 → 校验条告警）与**二次异常**（M4 保护误动 / 开关偷跳可直接强送）。

### 演练场景分类（双花瓣）

| 分组 | 场景 | 看点 |
| --- | --- | --- |
| 一、线路故障 · 保护正确动作（非故障段不停电） | L1–L6 | 差动两端切除；合环运行不停电；纵向联络解列不失负荷 |
| 二、开关站故障 · 母线 / 备自投 | K1 K2 K4 | 母线故障闭锁母联；两路进线失电由母联备自投转供 |
| 三、电源故障 · 变电站失电转供 | P1 P2 P3 | 变电站全停由对侧花瓣逐站转供；上级电源全停无电可转 |
| 四、自愈失败 · 拒动 / 越级 / 容量 | K3 R1 M3 M1 M2 | 拒动越级、主保护闭锁、备自投拒动、容量受限限电 |
| 五、故障性质 · 接地 / 瞬时 / 永久 | F1 T1 T2 | 单相接地不跳闸；重合成功 / 不成功 |
| 六、运行方式与二次异常 | O1 O2 M4 | 开环运行、母联常合并列、保护误动 / 开关偷跳 |

每类按“故障点 → 保护动作 → 隔离 → 转供”的顺序排布，便于连续演示；
分组名与编号随当前网架自动裁剪（单花瓣 / 环网 / 单辐射模板只保留适用的类别）。

详见 [`docs/接线约定.md`](docs/接线约定.md)。

## 发布到 GitHub

本仓库已做好完整的 Git 版本管理（含提交历史与版本标签），但本机无 GitHub 凭据，**首次推送**需你在 GitHub 上建好空仓库后执行：

```bash
cd 本项目目录
git remote add origin git@github.com:<你的用户名>/<仓库名>.git
git push -u origin main --tags
```

若使用 HTTPS：

```bash
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main --tags
```

> 本机 SSH 公钥请执行 `cat ~/.ssh/id_ed25519.pub` 获取，加到 GitHub → Settings → SSH and GPG keys 后即可免密推送。
